Testing APIs

Sending requests

Build a request, send it once, read the answer, and keep it in a collection — or bring your requests in from Postman, OpenAPI, or curl.

The request bar

Pick the method (GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS), type or paste the URL, and press Send (Ctrl+Enter).

You can paste more than a URL:

  • A curl command — for example from your browser's DevTools (Copy as cURL). The method, headers, body, and auth are filled in for you.
  • A URL with a query string — the parameters appear in the Params tab, where you can edit them one by one.
  • A path, like /orders — pick the server from the Base URL picker next to the method. See Choosing a base URL.

Press / to jump to the URL from anywhere on the page.

The tabs under the request

A small badge on a tab shows what is set — for example Checks 2/3 means two of three checks passed on the last Send.

The body

Choose None, JSON, or Text.

  • JSON is checked as you type: Valid JSON, or the error and where it is. Format JSON tidies the body with neat indentation. An empty JSON body sends {}.
  • Text is sent exactly as you type it.

Reading the answer

The Response panel shows:

  • the status (200 OK, 404 Not Found…), the time, the size, and the content type;
  • Body — see below;
  • Headers — response headers. Copy all copies them as Name: value lines. Sign-in headers such as Authorization and Set-Cookie are hidden as [redacted];
  • Checks — each rule with ✓ or ✕.

The Body tab has these views:

  • Pretty formats JSON with colours.
  • Raw shows the answer exactly as it came.
  • Preview — for HTML answers only — shows the page as a browser would. It is sandboxed: scripts on the page do not run.

The buttons on the right search the body (Ctrl+F; Enter and Shift+Enter move between matches), turn line wrapping on or off, copy the body, and download it as a file.

The app shows the first 64 KB of a large body; it says First 64 KB shown, and the size ends with +. Checks and saved values still use the whole answer.

If the request used Run first, a line under the status says what ran first and which values it found. When the request fails without an answer — for example Connection refused or Timed out — the panel says what that usually means and what to try.

Saving requests and collections

Press Ctrl+S (or Save request) to keep a request. Give it a Name and, optionally, a Collection — a folder that groups related requests, like Orders API. Pick an existing collection from the list or type a new name.

Once a request is saved, its collection and name appear under the URL. When you change it, ● unsaved appears next to the name: press Save (Ctrl+S) to update it, or Save as… to keep the original and save a copy.

Saved requests are plain files on your computer. Secrets in them (tokens, passwords, API keys) are kept encrypted, never in the file — see Privacy and your data.

The Saved requests panel

Saved requests are listed on the left, grouped by collection. Click one to open it. Search requests finds them by name, collection, URL, or method.

If you have unsaved changes, opening another request or pressing New request asks before it throws them away.

Importing from Postman, OpenAPI, or Swagger

Click Import (the arrow icon in the Saved requests panel), or choose Import from Postman or OpenAPI in the command palette. Then Choose a file, or drop it on the dialog:

  • Postman collections (v2.0 and v2.1) and Postman environments;
  • OpenAPI 3 and Swagger 2 files, as JSON or YAML (.json, .yaml, .yml).

Files can be up to 20 MB. No file? Click Or paste it instead, paste the JSON or YAML, and press Read it.

Before anything is saved, the app lists what it found — requests, folders, environments — and anything it could not bring across (for example, Postman scripts). Folders become collections; variables stay as {{variables}}.

Put the requests in collection names the collection they go into. It starts as the file's title; change it if you like (up to 60 characters). If that collection already has requests, they are kept and the new ones are added.

Your current requests are not changed. Press Import to save — the button says how many requests and environments it will add.

Tip After importing an OpenAPI file, set its server address once as a variable in an environment, and every imported request uses it.
