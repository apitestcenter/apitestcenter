Testing APIs

Sending requests

Build a request, send it once, read the answer, and keep it in a collection — or bring your requests in from Postman, OpenAPI, or curl.

The request bar

Pick the method (GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS), type or paste the URL, and press Send (Ctrl+Enter).

You can paste more than a URL:

  • A curl command — for example from your browser's DevTools (Copy as cURL). The method, headers, body, and auth are filled in for you.
  • A URL with a query string — the parameters appear in the Params tab, where you can edit them one by one.

Press / to jump to the URL from anywhere on the page.

The tabs under the request

TabWhat it does
ParamsQuery parameters (?page=2). Edit origin and path separately splits the URL into a base URL and a path.
HeadersExtra request headers, such as Accept or X-Request-Id.
AuthHow the request proves who it is: Bearer token, Basic (username and password), or an API key sent in a header or the query.
BodyFor POST, PUT and PATCH: JSON (checked as you type — Valid JSON) or plain text.
ChecksRules for a correct answer. See Checks.
Save valuesTake values from the answer for the next requests. See Chaining.
Run firstSend another saved request first, usually signing in. See Chaining.
Test dataRows from a CSV file as variables. See Chaining.
Load and GoalsThe load test and its pass/fail limits. See Load tests.
SettingsTimeout, maximum redirects, reusing connections, and skipping the TLS certificate check (for test servers with self-signed certificates only).

A small badge on a tab shows what is set — for example Checks 2/3 means two of three checks passed on the last Send.

Reading the answer

The Response panel shows:

  • the status (200 OK, 404 Not Found…), the time, and the size;
  • Body — Pretty formats JSON with colours; Raw shows it exactly as it came. You can search, copy, or download it;
  • Headers — response headers. Sign-in headers such as Authorization and Set-Cookie are hidden as [redacted];
  • Checks — each rule with ✓ or ✕.

If the request used Run first, a line under the status says what ran first and which values it found.

Saving requests and collections

Press Ctrl+S (or Save as…) to keep a request. Give it a name and, optionally, a collection — a folder that groups related requests, like Orders API. Saved requests appear in the Saved requests panel on the left; click one to open it, and search them by name, URL, or method.

Saved requests are plain files on your computer. Secrets in them (tokens, passwords, API keys) are kept encrypted, never in the file — see Privacy and your data.

Importing from Postman, OpenAPI, or Swagger

Click Import (the arrow icon in the Saved requests panel) and drop a file:

  • Postman collections (v2.0 and v2.1) and Postman environments;
  • OpenAPI 3 and Swagger 2 files, as JSON or YAML.

Before anything is saved, the app lists what it found — requests, folders, environments — and anything it could not bring across (for example, Postman scripts). Folders become collections; variables stay as {{variables}}.

Tip After importing an OpenAPI file, set its server address once as a variable in an environment, and every imported request uses it.
