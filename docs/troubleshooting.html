Help

Troubleshooting

Fixes for the things people run into — install warnings, being blocked by a firewall (429/403), certificates, missing variables, and updates.

Installing

Windows says “Windows protected your PC”. The app is new and not yet code-signed, so SmartScreen doesn't recognise it. Choose More info → Run anyway. This goes away as more people install it and once the app is signed.

macOS says the app can't be opened. The Mac version is a preview and not yet signed by Apple. Right-click the app → Open, then Open again. You only need to do this once.

Linux AppImage doesn't start. Make it executable — chmod +x APITestCenter-*.AppImage — and run it. Some distributions need libfuse2 for AppImages; the .deb doesn't.

My company network blocks the website download. Ask IT to allow github.com downloads, or install from the Microsoft Store when it's listed. The installed app then updates itself.

Blocked: 429 or 403

The report says Blocked by a rate limit or firewall, or most requests failed with 429 Too Many Requests or 403 Forbidden.

Something in front of the API — a CDN (Cloudflare, Akamai, CloudFront), an API gateway, or a firewall — decided the traffic looked like an attack and started refusing it. Often it keeps refusing for a while after the load drops, which the report calls a lockout.

What to do:

  1. Don't repeat it against a public site or someone else's API. It can get your address blocked for longer.
  2. Test a staging server without the limit, or ask the API's owner to allow your computer's address for the test.
  3. Lower the load. Use Requests per second with a modest rate instead of many simulated users with no think time. The report shows the rate at which refusals started — stay below it.
  4. If the API is yours: the 429 limit is a finding. It tells you what your gateway allows per caller.

Failures and errors

{{name}} is not defined. The request uses a variable that has no value. Pick an environment that defines it, add it, or check for a typo. In a collection run, the message also says which earlier request should have saved it.

401 Unauthorized. The token is missing or expired. Use Run first to sign in automatically, or update the token in your environment.

Certificate errors (self-signed, unknown issuer). Test servers often use certificates your computer doesn't trust. For those only, turn on Settings → Skip TLS certificate check on the request. Never use it for production.

Timeouts or “no answer”. The API didn't answer in time (default 60 seconds, in Settings → Timeout), the address is wrong, or a VPN or firewall is in the way. Try Send first: if a single request fails, a load test will too.

The load test didn't start because the first request failed. Before loading, the app sends the request once; if that fails, it stops so you don't send thousands of failing requests. Fix the single request, then run again.

The app

“Engine offline” or “k6 missing” at the bottom of the sidebar. The app's engine runs in the background; restart the app. If k6 is missing, reinstall — it ships inside the app.

Check for updates says it couldn't reach GitHub. Updates come from github.com. A company firewall or proxy may block it. Download the latest version from the website instead; your requests and history stay as they are.

Where are my files? How do I start fresh? See Privacy and your data. About → Open folder opens it. Close the app before moving or deleting files.

Still stuck? Write to support@apitestcenter.com with what you tried and, if you can, the exported JSON report.
